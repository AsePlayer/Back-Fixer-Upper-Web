# Public content pipeline

The browser loads generated JSON from `public/data/`. It never runs extraction or uses an API key. `content/catalog.json` preserves the full audit model; it is a Node build input, never a browser import.

The authoritative sanitized source store is `content/source/youtube/<channel-id>/`: `channel.json`, `sync-state.json`, and `videos/<video-id>.json`. Each video has cache schema 1, discovery format evidence, presence, optional source metadata and provenance. Only stable display/classification source fields survive sanitization. Direct media URLs, extraction noise, request headers, cookies, captions, comments and volatile counters are excluded. Files are text; videos and thumbnail files are never downloaded. Actions caches are optional and are not the source of truth.

This migration imported 1,308 sanitized extractor-cache records (5,639,043 bytes of per-video pretty JSON initially). The original generated snapshot was 8,779,162 bytes in the Windows source checkout; its logical revision is preserved. The new full JSON has LF line endings and equivalent parsed data. Source IDs/counts and SHA are in `baseline.json`. No source request reconstructed existing records.

For a missing old cache, `npm run content:bootstrap -- <snapshot.json>` reconstructs normalized, provenance-marked seeds from the snapshot. These are **not original extractor raw output**. `seedMetadata` preserves exact snapshot fields until enrichment; missing extractor metadata is queued. The new store requires its own successful full discovery even when an old cache was imported. Read `bootstrapSourceCheck` as inherited evidence, not a successful run of this project. Do not rerun bootstrap over an established store; it is an initial migration tool.

Cache schema 0 is the original ignored PC cache. `content:bootstrap -- <snapshot.json> <old-cache-root>` is the explicit 0 → 1 sanitizer/migrator; it copies only matching public inventory records and leaves the old cache untouched. Future schema changes should add a bounded explicit migration before raising the stored version. Unknown versions must be reviewed before regeneration. Catalog schema and classifier version are independent of this cache version.

`npm run content:classify` reads only local source records, runs the unchanged version-1 TypeScript classifier, applies `overrides.json` after automatic labels, then validates and generates runtime files. It makes no YouTube calls and never edits source records. For changed classification behavior, increment `CLASSIFIER_VERSION` in `src/content/classification/rules.ts`. Manual overrides are keyed by YouTube ID and require a reason; an empty label array intentionally clears that dimension. Keep unknown/unclassified entries discoverable. See [adding creators](../docs/ADDING_CREATORS.md).

The compact index includes all fields searched by the active source implementation: titles, creator, video ID, named body areas, subjects, topics and tags. The old search did not search descriptions. Full descriptions, automatic evidence, manual corrections and provenance stay in 64-record detail chunks. Revision hashes derive from content, not attempt times. `status.json` separately records generation time and source-check outcomes. Current and one previous public revision remain available; obsolete directories are pruned after publication. The service worker removes obsolete complete catalog caches only after a new complete cache is validated.

All sync attempts checkpoint per item atomically. Do not run simultaneous local writers. A crashed process can leave `sync.lock`; verify its PID is no longer running before removing that exact file. An ephemeral Actions runner has no old process locks to reclaim. `.tmp/`, logs and locks are ignored. Local dry-runs use an isolated ignored copy and never change committed source/public files; the runner removes its own checked scratch directory after a completed attempt. Interrupted `.tmp/update-*/` directories are disposable and can be cleared between runs.

Only reliable full discovery can infer absence. Missing entries are retained, never removed. Suspicious empty results or a per-surface full count below the configured 80% guard prevent reconciliation; investigate before deliberately adjusting the guard. Failed metadata never replaces a good value with nulls. Rate limits, bot challenges and provider blocking stop work without cookies or bypass attempts. A bounded rotating queue refreshes older metadata with 30-day eligibility on ordinary runs, instead of refetching all history every week.
